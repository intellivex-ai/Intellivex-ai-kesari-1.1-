## 2026-04-15 - [Fix IDOR in api/generate-image.ts]
**Vulnerability:** Insecure Direct Object Reference (IDOR) where any authenticated user could insert image messages into any other user's chat.
**Learning:** The application was missing explicit authorization checks (resource ownership verification) on the server side when performing operations via API endpoints that accept identifiers (like `chatId`) from the client.
**Prevention:** Always verify resource ownership (e.g., query the `chats` table to match the `user_id` with the authenticated `userId`) before allowing modifications or creations on that resource.
## 2025-02-23 - Prevent IDOR in Local Dev Server /api/messages Route
**Vulnerability:** Insecure Direct Object Reference (IDOR). The `GET /api/messages` and `POST /api/messages` endpoints in `vite-api-plugin.ts` trusted the client-provided `chat_id` and did not verify that the requesting `userId` actually owned the chat. Since the local dev server uses a Supabase service role key (bypassing RLS), any user could read or write messages to any chat ID.
**Learning:** In environments bypassing Row Level Security (RLS), like the local Vite dev server and certain Vercel API endpoints initialized with `SUPABASE_SERVICE_ROLE_KEY`, resource ownership verification must be manually implemented to prevent fail-open vulnerabilities. Furthermore, default or missing authentication fallback states (e.g., `userId === 'dev-user'`) must be strictly blocked before attempting database queries on endpoints handling sensitive data.
**Prevention:** Always verify resource ownership (e.g., `user_id` matches `userId`) explicitly in route handlers that bypass database RLS, and strictly handle default unauthenticated states by failing closed (`401 Unauthorized`) prior to any database queries.
