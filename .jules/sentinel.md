## 2026-04-15 - [Fix IDOR in api/generate-image.ts]
**Vulnerability:** Insecure Direct Object Reference (IDOR) where any authenticated user could insert image messages into any other user's chat.
**Learning:** The application was missing explicit authorization checks (resource ownership verification) on the server side when performing operations via API endpoints that accept identifiers (like `chatId`) from the client.
**Prevention:** Always verify resource ownership (e.g., query the `chats` table to match the `user_id` with the authenticated `userId`) before allowing modifications or creations on that resource.

## 2024-06-09 - [High] Fix IDOR vulnerabilities in dev server API endpoints
**Vulnerability:** The dev server endpoints (`/api/chat`, `/api/messages`, etc.) in `vite-api-plugin.ts` were subject to an Insecure Direct Object Reference (IDOR) vulnerability. They used a Supabase service role key (`SUPABASE_SERVICE_ROLE_KEY`) which bypasses RLS, but did not perform application-level ownership checks before allowing operations on resources like `chat_id`. This meant any authenticated user could potentially view or modify messages in chats belonging to other users if they knew or guessed the `chat_id`.
**Learning:** When writing server or serverless functions that interact with a database using a privileged token (like a service role key) instead of a standard user token, Row Level Security (RLS) is entirely bypassed. In these architectures, you must explicitly implement and enforce resource ownership checks within your application logic before performing any read or write operations.
**Prevention:** Always verify resource ownership (e.g., query the `chats` table to match the `user_id` with the authenticated `userId`) before allowing modifications or creations on that resource. Fail closed if the user is unauthenticated or does not own the resource.
