## 2026-04-15 - [Fix IDOR in api/generate-image.ts]
**Vulnerability:** Insecure Direct Object Reference (IDOR) where any authenticated user could insert image messages into any other user's chat.
**Learning:** The application was missing explicit authorization checks (resource ownership verification) on the server side when performing operations via API endpoints that accept identifiers (like `chatId`) from the client.
**Prevention:** Always verify resource ownership (e.g., query the `chats` table to match the `user_id` with the authenticated `userId`) before allowing modifications or creations on that resource.
## 2025-02-20 - HTML Injection/XSS Breakout in Iframe Sandbox
**Vulnerability:** A cross-site scripting (XSS) / HTML injection vulnerability in `src/stores/workspaceStore.ts`. User-provided code was directly interpolated using `${code}` into the `<script>` tag of an iframe's `srcdoc`. This allowed attackers to break out of the script context using payloads like `</script><script>alert(1)</script>`.
**Learning:** Even within an iframe sandbox with `allow-scripts`, direct string interpolation of user input into HTML structures (like `srcdoc`) is a vector for context breakout. The code must be properly encoded for the context it is being injected into (in this case, inside a script tag within HTML).
**Prevention:** When injecting dynamic code strings into a script block within HTML, use `eval(${JSON.stringify(code).replace(/</g, '\u003c')})`. `JSON.stringify` ensures the code is safely represented as a JavaScript string literal, and escaping `<` prevents the HTML parser from prematurely closing the script block, mitigating the XSS vector while maintaining functional execution.
