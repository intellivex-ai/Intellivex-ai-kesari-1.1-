## 2025-02-27 - [CRITICAL] Fix IDOR in Vite API Plugin Message Endpoints
**Vulnerability:** The `GET /api/messages` and `POST /api/messages` endpoints in the local development environment (`vite-api-plugin.ts`) failed to verify that the requested `chat_id` belonged to the authenticated `userId`. Because it used `sbFetch` with the `SUPABASE_SERVICE_ROLE_KEY` (which bypasses RLS), this created a critical Insecure Direct Object Reference (IDOR) vulnerability, allowing any user to read or write to any chat by simply supplying its `chat_id`.
**Learning:** Development-only API mock plugins often drift from production serverless handlers (`api/messages.ts`) in terms of security controls. Using service role keys without robust, manual ownership validations completely bypasses Supabase Row Level Security (RLS) protections, causing the endpoint to fail open.
**Prevention:** When building custom PostgREST wrappers or using service role keys in any environment, authorization checks must be implemented explicitly and must fail securely (e.g., verifying that the fetch operation returned a valid array where `chatData[0].user_id === userId`, and blocking if it returned an error object or an empty array).
